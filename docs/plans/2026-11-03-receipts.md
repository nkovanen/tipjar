# Contributor receipt observations

Build the delegated first slice with standard-library code in `receipts.py` and
small CLI, text and schema additions. Existing contracts and authorization gates
stay independent. A receipt records a public GitHub PR; it never certifies agent
involvement, tests, quality, consent or permission.

`tipjar receipt owner/repo#N --output FILE` reads repository metadata and PR
detail through two fixed GET endpoints. Require public metadata, exact canonical
name/URL, stable positive numeric repository/PR/author identities, full head/base
SHAs, refs, typed state/draft/merge fields and valid UTC timestamps. Reject any
missing, inconsistent or unknown fact before exclusive file creation. Store
schema 0.1, observed time, endpoints, merge facts and explicit trust/refresh notes.
This is a non-atomic snapshot; no automatic refresh or overwriting.

`tipjar impact FILE...` is offline: 1–100 regular, non-symlink files, each at most
64 KiB of strict UTF-8 JSON. Reject duplicate keys, unknown versions/properties,
invalid facts, future observations and conflicting numeric identities. Use the
latest timestamp per numeric repository/PR identity regardless of argument
order; conflicting equal-time snapshots reject. Identical snapshots deduplicate.
Count unique PRs, open (including drafts), closed (unmerged), merged, and unique
repositories represented. List the selected snapshots for dashboard consumers. Label
all results self-reported recorded observations; no authenticated contribution,
LOC, quality or test metrics. Fail the entire summary on invalid input.

Plan: (1) meaningful failing tests with fixed fake GitHub and temporary files;
(2) module, packaged receipt/output schemas, CLI and text; (3) public examples and
generated output reference; (4) focused/full tests and build/install validation;
(5) merge latest origin/main, rerun relevant checks, commit for controller review.
Independent review, publication and integration belong to the controller.
