# README invitations

Run `tipjar badge owner/repo` offline. Paste its exact snippet at byte zero of the
actual repository's root README.md, including the blank third line. The clickable
badge says “Agent-work tips welcome” and links to onboarding for that repository.
The CLI reads the source bytes; it never fetches the SVG or follows its link.

Only the fixed official prefix is recognized. LF and uniform CRLF are supported;
titles may follow the required blank line. Copied parent links, duplicate intent,
wrapped examples, changed URLs, unsupported markers and incomplete reads are
unknown and block readiness. Plain README files remain undeclared. Use the JSON
manifest when the project title should come first.

At the same pinned commit, `.tipjar.json` always takes precedence. Closed, invalid,
unreadable and unsupported manifests cannot be rescued by a README welcome.
Removing JSON requires deliberately retaining or removing the README invitation.

`tipjar jar owner/repo` reports the actual file path, source kind and verified
blob/digest. Welcome supplies only invitation: issue approval, policy compliance,
implementation authority and exact publication authority remain separate.
Discovery reads the actual issue source, including when targeting a tracker fork.

A fork with a copied upstream header is unknown. Its owner must intentionally
correct its repository parameter or remove the header; the CLI never edits forks.
No fork welcome is required, but its own policy must be completely assessed.

New reports use output 4 and find-jars-report/2 (two page-1 searches, five hits
each, one shared inspection pass). Search indexing can lag or omit repositories.
At most 52 gh invocations (58 with budget instrumentation) are attempted. Find is
uncached and supplies no authority. Snapshot imports retain explicit /1 support.

Task 0.3 is still unpublished. Its required inventory format 4 and source-kind,
path, blob and manifest-presence bindings require old format-3 drafts to be
reprepared and freshly reviewed/authorized. No mandate or hash is migrated.
Published tasks 0.1/0.2 retain manifest-only resolution and historical inventory
semantics. Output schemas 1–3 remain archived unchanged.

The static site and asset are deployment inputs. This change does not establish
that the public URLs are deployed or that any external repository has adopted it.
