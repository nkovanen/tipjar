# Tipjar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. No subagents are authorized by this document; the controller owns independent review and execution assignments. Steps use checkbox syntax for tracking.

**Goal:** Expose pinned repository invitations for agent work while keeping explicit no-jar targeting available and existing authority decisions separate.

**Architecture:** A small `tipjar` module validates and reads one source manifest. First expose a read-only inspection command; then integrate the result with the existing policy inventory, live guards and an opt-in discovery filter. Task/evidence formats stay unchanged.

**Tech Stack:** Python 3.10+, standard library, existing GitHub GET client, unittest and packaged JSON Schemas; no runtime dependencies.

**Spec:** [Tipjar design](../specs/2026-11-03-tipjar-design.md). Controller manifest/staging rulings are recorded in the spec; this document is not implementation authority. Commands below describe future work, except verification of today's documentation.

## Global Constraints

- An absent jar means **undeclared**, not closed, forbidden, approved or authorized.
- Root must be an object. Only `schema_version`, `status`, `wanted`, `boundaries` are allowed.
- Version is exactly the string `0.1`; status is exactly `welcome` or `closed`.
- Maximum raw file size: 16,384 bytes, including whitespace.
- Each array has at most 16 distinct strings. Each string is 1–500 Unicode code points and nonblank under the spec's explicit Unicode White_Space set (U+0085 is blank; U+FEFF is nonblank); reject C0 controls and DEL.
- No path glob language or automatic natural-language policy evaluator in 0.1.
- Manifest 0.1 has **no inheritance**.
- Keep task/evidence 0.1 and 0.2 and host-context schemas unchanged.
- Keep `.agent-contrib.json` exactly as it is; no migration, aliases or dual-file approval precedence.
- Controller selects the release target. Keep library, CLI/module and single canonical Skill compatible; do not push, publish, contact maintainers or merge without actual authorization.

## Review Focus

Each item has a named regression in its owning task.

- Contents 404 after a listed jar must be unknown, never undeclared (Task 1).
- A malicious blob identity/symlink must not supply source policy (Task 1).
- A welcome cannot cancel owner/source prose refusals, including unassessed links (Task 3).
- An old contract must notice newly added/changed jars without changing its format (Task 3).
- One unknown repository must remain visibly incomplete beside a welcomed repository (Task 4).

## File map and sequencing

New `agent_contribute/tipjar.py` owns pure parsing, fixed GET inspection and jar-only safety comparisons. Existing `policy.py` owns source inventory and its versioned digest; `core.py`/`lifecycle.py` own readiness and source/target identity. `cli.py`, `outputs.py`, `textfmt.py` and output schemas own the public command surface. Keep jar data out of task schema objects. Do not refactor unrelated modules.

Tasks 1–2 form the runnable minimum; it is an inspection tool, not a complete Tipjar contribution workflow. Tasks 3–4 are later increments. Do not advertise enforced invitations until Task 3 is complete. No stage adds global repository discovery. Coordinate release-version files with other work instead of independently changing every version statement here.

### Task 1: Strict manifest parser and pinned reader

**Files:** Create `agent_contribute/tipjar.py`, `agent_contribute/tipjar.schema.json`, `tests/test_tipjar.py`.

**Interfaces:**

- `parse_manifest(data: bytes) -> dict`: returns validated source object, preserving omission of optional fields; raises `core.ProtocolError('invalid_tipjar', ...)` on invalid data and `unsupported_tipjar_schema` on an unknown version. Errors are bounded and do not echo full input.
- `inspect_jar(repository: str, client=None, *, commit: str | None = None, metadata: dict | None = None) -> dict`: returns the exact `tipjar-report/1` shape in the spec, including null provenance on early failure. Default resolves current default-branch tip. An explicit commit is used only for historical reads/internal reuse and validated as a full SHA.
- `same_declaration(before: dict, after: dict) -> bool`: true only for complete reports with equal repository identity, state and byte digest (absence has null digest); commit advancement alone does not change a declaration.
