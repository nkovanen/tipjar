# Find Jars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. No subagents authorized here; controller arranges review/build. Steps use checkbox syntax.

**Goal:** Find up to ten public repository jar candidates and independently verify their own welcome declarations.
**Architecture:** New `find.py` validates one search page, then reuses the shipped jar reader. Existing CLI/schema/text layers expose the bounded observations without authority changes.
**Tech Stack:** Python 3.10+, standard library, existing GET client, unittest; no new runtime dependencies.
**Spec:** [Find jars design](../specs/2026-11-03-find-jars-design.md); read it and the reviewed jar design before implementation.

## Global constraints

- At most 10 candidate inspections; each uses one metadata call + at most three reader calls with supplied metadata + at most one final metadata call = five.
- Command work is <=51 logical GET calls and <=51 gh invocations (1 search, <=50 core), sequential, no application retry/sleep/pagination/fallback/backfill. Two budget reads allow three invocations each: <=57 total; raw HTTP count is uninstrumented and may exceed invocation count via internal gh redirects.
- No task/evidence/host-context changes, registry, topic writes, payments, crawling, issue/PR reads, automatic contact, or changes to supplied-list `--welcomed-only`.
- Reuse the shipped jar-report schema, without new fields. No runtime dependencies or changes to the canonical Skill.

## Review focus

- Conflicting duplicate ids must invalidate all conflicting hits before any jar reads (Task 1).
- Search visibility may differ from fresh metadata; private data must not be emitted (Task 2).
- Metadata can change after the pinned jar read; final eligibility is required (Task 2).
- A retrying helper/cache must not silently inflate or skip gh invocation observations; redirects must not bypass identity checks (Task 2).
- Empty, truncated and server-incomplete batches need different truthful provenance (Task 3).
