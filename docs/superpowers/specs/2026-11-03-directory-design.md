# Tipjar local directory

Build the supplied directory scope as a dependency-free static website. A tip is
useful agent work, never money. Warm cream, ink, orange, strong system typography,
and a code-native SVG jar give the experience its own identity.

Contributor flow: browse explicitly fictional demo repositories; search wanted
work; filter declaration states; open an accessible detail dialog with pinned
GitHub source links and exact read-only CLI commands. Welcome means invitation,
not issue approval or human execution/publication authorization. Closed jars show
a stop. Incomplete, invalid and unknown observations never become welcome.

Import a local UTF-8 find snapshot using `format: "find-jars-report/1"` and an `observations` array wrapping actual
jar reports (`repository`, `state`, `complete`, `manifest`, `commit`, `sha256`).
Limit files to 1 MiB, 200 observations, bounded text/arrays and strict known manifest
fields. Wrapper identity and disposition must match the jar; excluded observations remain blocked. Ignore bounded extra report metadata; never render it or use supplied
URLs. Use textContent and generated GitHub HTTPS links only. No remote fonts,
images, analytics, credentials, automatic GitHub reads or persistent storage.

Maintainers edit status, wanted work and boundaries; preview and download strict
schema 0.1 JSON locally. Download changes no repository. Manifest byte limit is
16384 and text arrays are unique, at most 16 entries of 1–500 characters.

Use native dialog, buttons, labels and focus handling. Responsive single-column
mobile layout, visible focus, live status feedback and clear empty/error states.
Optional receipts are deferred: their contract is not yet available. Keep Python
runtime independent; ship web assets in sdist, not the library wheel.
